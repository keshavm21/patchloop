This file is generated: `python -m patchloop.eval.publish` fills `results/REPORT.template.md` with numbers computed from the `records.jsonl` files in `results/` and the labels in `results/error_analysis.json`. "pending" means a run hasn't finished yet.

**Setup.** Main model `openai/gpt-oss-20b`, temperature 0, `reasoning_effort: low`, prompts v1, up to 3 attempts, results on the **test splits** only. Commits behind the records: HumanEvalFix `0e2fd95`, `307dd51`, `88a55bf`, MutBench `0e2fd95`, `a89dff1`, `d235a2b`, `d2c09b2`. Repair % is the mean over tasks of each task's solve rate across its repeats, with a 95% bootstrap interval over tasks, and configs are compared with a paired bootstrap. A run counts as solved only if the **hidden** tests pass, and the model never sees them.

- **Wrong diagnosis** (12): the model rewrote the function on its own reading of the task instead of finding the one-token bug, or fixed a line that wasn't broken.
- **Partial fix** (9): the right idea, but an edge case is still wrong (empty input, `n = 0`, floats overflowing on large EvalPlus inputs).
- **Benchmark noise** (7): the reference disagrees with its own spec. EvalPlus feeds unsorted arrays to "two sorted arrays", expects one particular solution of `ax + by = n`, or one exact order of combinations. Several of these tasks fail for both models, which supports the label.
- **Over-defensive validation** (3): the model added `raise ValueError` checks nobody asked for, and the hidden inputs trip them.
- **Output-format failure** (1): the reply wasn't a whole file in one code block.
- **No hard-coding.** None of the runs that pass the visible tests and fail the hidden ones special-cases the visible inputs. Overfit here means partial fixes and spec disagreements, not gaming the tests.

## Five examples

1. **A repair from feedback** (MutBench 131, `reverse_vowels`). Attempt 1 reversed the list of vowels and then popped from its end, reversing it twice, so the output was unchanged. The feedback showed `assert reverse_vowels("USA") == "ASU"` failing with `'USA'`, and attempt 2 switched to indexing from the end. This is the loop doing what it's for.
2. **Benchmark noise** (MutBench 597, `find_kth`). The task says "two sorted arrays", and the model wrote a correct merge of two sorted arrays. The reference concatenates and sorts, and the EvalPlus inputs aren't sorted, so the spec-following answer fails.
3. **Over-defensive validation** (MutBench 391, `convert_list_dictionary`). The model added a check that all lists have the same length and raised `ValueError` otherwise. The reference zips, which truncates, and the hidden inputs include unequal lengths.
4. **Rewriting the spec** (HumanEvalFix 127, `intersection`). The model fixed `is_prime` but missed the missing prime check, and edited the docstring's explanation to match its wrong code. Hidden tests judge the original behaviour, so it fails. It's a reminder that the model edits whatever is in the file, including the spec.
5. **A spec the model reads differently** (HumanEvalFix 91, `is_bored`). "Count sentences that start with the word I": the model counted sentences starting with any "I…", such as "It" or "Is", which the hidden tests reject.

## Limitations

- 1 repeat(s) on MutBench and 2 on HumanEvalFix for the headline comparison, on the free tier. Groq isn't deterministic at temperature 0, so intervals are wider than with three repeats. The feedback ablation and the attempts sweep ran once, on MutBench only, and reflect mode (`configs/full_reflect.yaml`) wasn't run.
- Hidden verdicts on the first 96 MutBench main-model runs and on the second-model runs were re-judged with the benchmark's 20 s per-test timeout (`patchloop rejudge`), after the eval had used 5 s by mistake. The agent's decisions only depend on the visible tests and were unaffected; the `rejudged` block in each record keeps the earlier verdict.
- Function-level Python only; tests are a proxy for correctness, and 13 of MutBench's 200 tasks start with code that already passes every visible test.
